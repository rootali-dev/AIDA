## 🛠️ ۲. کلیدواژه‌های طلایی Rust که توی پروژه می‌بینی

وقتی کدهای Rust پروژه فایروال رو می‌خونی، مدام با چند کلمه و ساختار خاص مواجه میشی. بیا معنیشون رو ساده کنیم:

### 🔹 ۱. `let` و `let mut` (تعریف متغیر)

در Rust متغیرها به‌صورت پیش‌فرض **غیرقابل تغییر (Immutable)** هستند!

Rust

```
let x = 10; // نمیتونی بعداً بنویسی x = 20 (ارور کامپایلر)
let mut y = 10; // کلمه mut یعنی Mutable؛ حالا می‌تونی تغییرش بدی
```

### 🔹 ۲. `fn` (تعریف تابع)

به جای `def` در پایتون یا تایپ بازگشتی در C++، از `fn` استفاده میشه:

Rust

```
// ورودی x از نوع u32 و خروجی تابع هم یک u32 است
fn add_one(x: u32) -> u32 {
    x + 1 // توی راست اگر خط آخر سمیکالن (;) نداشته باشه، خودش return میشه!
}
```

### 🔹 ۳. علامت `&` (Reference / Reference به حافظه)

وقتی قبل از یک متغیر `&` می‌ذاری (مثل `&ctx`)، یعنی: _«خودِ متغیر رو کپی نکن یا صاحبش نشو، فقط یک آدرس/اشاره‌گر بده تا بهش نگاه کنم.»_ (دقیقاً مثل Referenceها در C++).

## 🚦 ۳. سیستم مدیریت خطای Rust (عدم استفاده از `null`)

توی زبان‌های دیگه اگر چیزی وجود نداشته باشه یا خطایی رخ بده، متغیر `null` میشه و برنامه کرش می‌کنه. در Rust چیزی به اسم `null` وجود نداره! به جاش دو ساختار عالی داریم:

### 🅰️ `Option<T>` (چیزی هست یا نیست؟)

وقتی یک تابع ممکن است مقداری داشته باشد یا نداشته باشد:

- **`Some(value)`**: یعنی مقدار وجود دارد.
    
- **`None`**: یعنی مقداری وجود ندارد.
    

### 🅱️ `Result<T, E>` (عملیات موفق بود یا ارور داد؟)

مثل کدی که در تابع `try_xdp_hello` دیدیم:

- **`Ok(value)`**: یعنی همه چیز عالی بود و خروجی اینه.
    
- **`Err(error)`**: یعنی عملیات با خطا مواجه شد.
    

### 🔍 ساختار `match` (بررسی حالت‌ها):

برای باز کردن این `Option` یا `Result` از `match` استفاده می‌کنیم:

Rust

```
// اگر تابع به ما نتیجه داد، بررسیش کن:
match result {
    Ok(ret) => ret,                      // اگر موفق بود، مقدار ret رو بده
    Err(_)  => xdp_action::XDP_ABORTED,  // اگر ارور بود، این مقدار رو بده
}
```

## 🎯 چطوری از این به بعد کدها رو بلیت‌به‌بلیت بخونی؟

بیا کدی که جلسه اول بررسی کردیم رو با این دیدگاه جدید دوباره بخونیم:

Rust

```
pub fn xdp_hello(ctx: XdpContext) -> u32 { ... }
```

- **`pub fn`**: یک تابع عمومی (Public Function).
    
- **`ctx: XdpContext`**: ورودی تابع به اسم `ctx` و از جنس ساختار `XdpContext`.
    
- **`-> u32`**: خروجی این تابع حتماً باید یک عدد مثبت ۳۲ بیتی (مثل اکشن‌های XDP) باشه.
    

Rust

```
unsafe fn try_xdp_hello(ctx: XdpContext) -> Result<u32, u32> { ... }
```

- **`Result<u32, u32>`**: این تابع یا یک `Ok(u32)` برمی‌گردونه (در صورت موفقیت) یا یک `Err(u32)` (در صورت خطا).
